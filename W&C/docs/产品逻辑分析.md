# W&C · 产品逻辑分析 & 信息架构重构建议

> 日期：2026-10-22 ｜ 目的：风格已 OK，现在诊断"逻辑不舒服"的根因，并给出重构方案
> 参照：Apple Fitness、薄荷健康、Keep、Streaks、Habitify 等健康/习惯类 App 的底层设计逻辑

## 一、一句话诊断

**当前 App 是"工作台"思维，不是"产品"思维**——它把一堆功能平铺成 5 个 Tab，但没有一条清晰的主线让用户「打开→记录→看到反馈→明天继续」。

---

## 二、当前信息架构的问题

### 现有结构
```
侧边栏：W&C 健身减脂 / 英语学习
   └ 健身模块 5 Tab：记录 / 打卡 / 数据 / 计划 / AI顾问
顶部：W ⇄ C 全局切换人
```

### 问题 1：Tab 职责重叠，信息被打散

| Tab | 现在放了什么 | 问题 |
|---|---|---|
| 记录 | 录入入口 + 今日卡片 | 和「打卡」都展示"今天吃了啥"，重叠 |
| 打卡 | 日期 + 三环 + 打卡清单 + 当日记录 | 这其实**才是"今天"该有的样子** |
| 数据 | 净摄入 + 体重趋势 + 宏量 | 数据被拆到三个页面，拼不起来 |
| 计划 | 15 天任务清单 | 和「打卡」是两个概念，打架 |
| AI顾问 | 聊天 | 是"功能"，不是"目的地" |

结果：用户不知道「我要看今天的状态该去哪个 Tab」。

### 问题 2：单人和双人的视角不自洽

- 顶部「W ⇄ C」是全局切换，切完记录页只显示当前人
- 但打卡页又同时显示情侣双人卡
- 到底是「我的视角」还是「我们的视角」？用户会懵

### 问题 3：导航层级过重

侧边栏（模块）+ 底部 Tab（功能）+ 顶部切人 + 模块内子 Tab —— 四层导航，典型的工作台遗风。

### 问题 4：两个"打卡"概念冲突

- 「打卡」Tab 打的是「三餐 + 体重」
- 「计划」Tab 打的是「每天 2 个任务」
- 用户：我到底要打卡什么？

### 问题 5：英语学习混入减肥 App

这是 WorkBuddy「工作台」时代的遗留，两个完全不同品类的产品塞一个壳里，稀释了「减脂」这个核心。

## 三、健康/习惯类 App 的底层设计逻辑（黄金标准）

1. **打开即「今天」**——首页就是今日状态，不是功能列表
2. **一个动作 = 一次记录 = 立即反馈**——拍照/一句话/点一下，下一秒进度环就变
3. **进度可视化**——环、连续天数、曲线，让努力「看得见」
4. **情感钩子**——连续打卡 streak、双人 PK、鼓励语，制造「舍不得断」的黏性
5. **少即是多**——3~4 个 Tab 封顶，越少越聚焦

参照：
- **Apple Fitness**：一屏三环搞定今天，历史和更多收进次级页面
- **薄荷健康**：首页「今天」（饮食+运动+体重），底部 4 Tab
- **Streaks**：每天 N 个习惯，点一下完成，极简到极致
- **Keep**：首页今天训练 + 数据 + 我的

## 四、重构建议

### 方案 A（推荐）：3 Tab + 悬浮录入按钮

```
底部 Tab：今天 / 趋势 / 我的
录入：首页右下角大「+」按钮（拍照/语音/手动），不占 Tab
```

| Tab | 职责（唯一） |
|---|---|
| **今天**（首页） | 三环 + 今日打卡清单（早午晚体重）+ 情侣双人进度 + 今日计划任务 |
| **趋势** | 体重曲线 + 连续打卡天数 + 历史回顾 |
| **我的** | 计划管理、AI顾问入口、数据详情、设置、英语学习收进这里 |

- **双人逻辑统一**：「今天」页是**双人合并视图**（两人各吃多少、各打卡几项），录入时才选人（默认上次选的人），顶部不再需要全局切人
- **计划并入今天**：今天要做的 2 个任务直接显示在首页，不再单独一个 Tab

### 方案 B：4 Tab（录入体验更完整）

```
底部 Tab：今天 / 记录 / 趋势 / 我的
```

- 保留「记录」作为独立 Tab（录入 + 待确认 + 今日流水），适合「记录频率高、想单独管理」的场景
- 其余同方案 A

---

## 五、我的推荐

**方案 A**。理由：
1. 符合「打开即今天」的第一原则，用户粘性最高
2. 录入用大按钮，比占一个 Tab 更符合"记录要无感"
3. 3 个 Tab 最极简，配合你已经定好的视觉风格，产品感立刻出来

但你是设计师、也是使用者——**你来拍板 A 还是 B**。定了我就按新信息架构重构导航和页面归属，功能一个不丢，只是重新归位。
